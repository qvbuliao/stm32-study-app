# STM32 五天速通学习器

一个**单文件离线学习 App**，配合 B 站《STM32入门教程-2023版》（BV1th411z7sn）使用，
覆盖 **P4 `[2-2] 新建工程` → P14 `[6-2] 定时器定时中断 & 定时器外部时钟`**，共 11 集、约 6 小时 47 分。

针对你的情况做了三处专门设计：
- **没有 C 语言基础** → 「急救」页 11 节，从「一段真实 STM32 代码逐行翻译」讲起，不需要先学完 C 语言
- **没有 STM 基础** → 「课程」页 11 章 25 节详解，比视频更细，含框图、表格、可复制代码
- **每天 3-4 小时** → 计划按 42 项可勾选任务拆解，标了「必做 / 可跳 / 项目」，时间不够时知道该舍什么

## 怎么用（三种方式，各解决不同场景）

先看这张表，挑适合你的：

| 方式 | 要联网吗 | 离开 WiFi 能用吗 | 需要电脑吗 | 适合场景 |
|---|---|---|---|---|
| **A. GitHub Pages** | 首次联网；之后**能离线** | ✅ 能 | 不需要 | **日常使用，推荐** |
| **B. 局域网** | 要同一 WiFi | ❌ 不能 | 要 | 临时试玩、传文件前的预览 |
| **C. 传文件到手机** | 完全不用 | ✅ 能 | 一次性 | 彻底不想碰网络 |

> [warn] **重要：方式 B 的 `http://10.40.85.98:8000/...` 是内网地址，手机一离开这个 WiFi 就永久失效。**
> 它只在"电脑开着服务 + 手机连同一个 WiFi"时有效，不要把它当作日常入口。
> 你要的「流量也能上 + 没网也能看」，请用**方式 A**。

### 方式 A：GitHub Pages（推荐 —— 一个网址同时满足两种需求）

用手机或电脑浏览器打开：

```
https://<你的GitHub用户名>.github.io/stm32-study-app/
```

**第一次打开后，它就自己存到手机里了**（Site Worker 离线缓存），之后：

- **用流量、换 WiFi、甚至飞行模式**都能打开
- 在浏览器菜单选「添加到主屏幕」，桌面会出现一个 **STM32 图标**，点开是全屏 App
- 内容和进度都存在本地，不再依赖网络

想“装”成 App，见下面的「添加到主屏幕」。

### 方式 B：局域网免传文件（临时预览用）

把仓库下到电脑，然后：

```powershell
node serve.mjs            # 默认 8000 端口；也可 node serve.mjs 8080
```

窗口会打印手机可直接访问的网址，形如：

```
[WLAN]  http://10.40.85.98:8000/stm32.html
```

手机连**同一个 WiFi**，在浏览器输入这个网址即可。服务窗口关掉网址就失效。
`serve.mjs` 只对外提供成品文件，不会暴露源码和脚本。

> [warn] **校园网 / 公司网最容易卡在这里**，两个原因：
> 1. **防火墙**：Windows 首次监听会弹「允许应用通过防火墙通信」，
>    必须点**允许访问**并勾上「专用网络」「公用网络」。没弹窗或误点了拒绝，
>    就需要管理员权限手动放行（下面的命令要在**管理员** PowerShell 里跑）：
>    ```powershell
>    New-NetFirewallRule -DisplayName "STM32 App 8000" -Direction Inbound `
>      -Protocol TCP -LocalPort 8000 -Action Allow -Profile Any
>    ```
> 2. **客户端隔离**：很多校园网 / 公共 WiFi 会禁止同一网络内设备互访，
>    这种情况下**任何局域网方案都不通**（换端口也没用）。
>
> 排查：先在**电脑自己的浏览器**打开该网址（通 = 服务没问题），
> 再在**手机**打开（不通 = 防火墙或客户端隔离）。
>
> 局域网只是省去传文件的便利；不通就直接走方式 A 或 C。

### 方式 C：把文件传到手机（完全离线）

只需要传 **`STM32-5天速通.html`** 这一个文件。任选一种：

| 方式 | 做法 |
|---|---|
| **微信 / QQ** | 把文件发到「文件传输助手」，手机上点开 → 右上角「用其他应用打开」→ 选浏览器 |
| **网盘** | 传到百度网盘 / 阿里云盘，手机端下载后点开 |
| **数据线** | 直接拷到手机存储，用「文件管理」找到它并点开 |

装好后**完全离线，飞行模式下也能用**，不依赖网络。

### 用浏览器打开

点开文件后选 **Chrome**（安卓）打开。**不需要联网**，所有内容都在文件里。

### 添加到主屏幕（关键）

- **Chrome（安卓）**：右上角 `⋮` → **添加到主屏幕** → 命名「STM32」→ 添加
- **Edge / 其他浏览器**：菜单里的「添加到主屏幕」或「安装应用」
- **iPhone**：Safari 打开 → 分享按钮 → **添加到主屏幕**

完成后桌面会多一个图标，**点开就是全屏 App**，没有浏览器地址栏，和原生 App 一样用。
因为文件是离线的，**飞行模式下也能打开**。

> [warn] 不要用微信内置浏览器打开——它不支持「添加到主屏幕」。
> 一定要选「用其他应用打开」→ Chrome。

### 确认能记住进度

随便勾一个任务，然后**退出 App 再打开**，如果勾还在，说明进度保存正常
（进度存在手机本地 `localStorage`，换页面、关浏览器都不会丢）。

## 离线是怎么实现的

App 用了 **Service Worker**（`sw.js`）做离线缓存：

1. 你第一次用 https 打开页面时，浏览器把内容存进本地缓存
2. 之后**没有网络也直接从缓存读取**，页面照常打开
3. 有网络时会在后台静默更新，下次打开自动是新版

所以**只要打开过一次，就永久可用** —— 用流量、换 WiFi、飞行模式都没问题。

| 打开方式 | 是否注册 SW | 能否离线 |
|---|---|---|
| `https://` GitHub Pages | ✅ 会 | ✅ **能** |
| `http://localhost` | ✅ 会（本地测试） | ✅ 能 |
| `http://内网IP` | ❌ 浏览器不允许 | ❌ 只能同 WiFi |
| `file://` 本地文件 | ❌ 不需要 | ✅ 本来就是本地文件 |

> 说明：`http://` 协议下浏览器禁止注册 Service Worker（安全限制），
> 这就是为什么**局域网地址无法离线**。`file://` 方式本身不联网，所以也不需要 SW。

**验证过的**：`node offlinetest.mjs` 会起本地服务、加载页面、用 CDP 切断网络、
再重新打开，确认断网后 5 天计划 / 30 道题 / 勾选交互全部正常。

## 上传到 GitHub（第一次）

在 `stm32-app` 目录下依次执行：

```powershell
# 1. 设置提交身份（只需一次，全局有效）
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"

# 2. 初始化仓库并提交
git init -b main
git add -A
git commit -m "STM32 五天速通学习 App：单文件离线版 + 构建与测试脚本"

# 3. 关联远程仓库（先在 GitHub 网页上建好空仓库 stm32-study-app，不要勾选 README）
git remote add origin https://github.com/<你的用户名>/stm32-study-app.git

# 4. 推送（会弹出浏览器让你登录 GitHub，登录一次即可）
git push -u origin main
```

推送时会弹窗要求登录 —— 选 **Sign in with your browser**，浏览器里授权就行，
**不需要手动生成 token**（本机已配有 Git Credential Manager）。

之后日常改动的流程：

```powershell
node build.mjs            # 改了 data.js / data2.js / template.html 后重新生成
node check.mjs            # 自检
git add -A
git commit -m "说明这次改了什么"
git push
```

## 五天计划总览

| 天 | 视频章节 | 时长 | 核心目标 |
|---|---|---|---|
| **Day 1** | `[2-2]` 新建工程 | 42 min | 把工程建起来，烧录一个能闪灯的程序 |
| **Day 2** | `[3-1]` `[3-2]` | 74 min | GPIO 输出五步法、LED 闪烁 / 流水灯 |
| **Day 3** | `[3-3]` `[3-4]` | 77 min | 按键、**消抖对比实验**、传感器输入 |
| **Day 4** | `[4-1]` `[4-2]` `[5-1]` | 76 min | OLED 调试工具 + 中断系统 + EXTI |
| **Day 5** | `[5-2]` `[6-1]` `[6-2]` | 137 min | 定时器时基单元、参数计算、外部时钟 |

### 时间不够的时候，按这个顺序舍

1. **先舍** `[5-2]` 的旋转编码器计次（50 min）——它在功能上被 `[6-7]` 硬件编码器接口覆盖，晚点学不影响
2. **再舍** `[3-2]` 的无源蜂鸣器——要等 `[6-4]` 学 PWM 才做得了，今天本来也做不了
3. **绝对不能舍**：`[2-2]` 工程架构、`[5-1]` 的中断系统、`[6-1]` 的时基单元
   —— 这三个是后面所有章节的地基。地基塌了，`[6-3]` 以后的 PWM、输入捕获、编码器接口全都听不懂

### 数据语法约定

源文件里的正文在**模板字符串**中，所以：

- **行内代码**：`[[GPIO_Init()]]` → 渲染为 `<code>`
- **代码块 / 框图**：单独一行 `[[[c]` 或 `[[[text]` 开头，单独一行 `]]` 结尾
  （`build.mjs` 会自动统一成标准围栏）
- **加粗**：`**文字**`
- **小标题**：`[h3] 标题` 或 `## 标题`
- **提示框**：`[warn]` `[ok]` `[bad]` 开头的行 → 黄色 / 绿色 / 红色提示框
- **表格**：标准 Markdown 表格；单元格里想写字面竖线用 `\|`

> 注意：**不要**在正文里用单个反引号，会和模板字符串冲突——一律用 `[[ ]]`。

### 自检脚本

| 脚本 | 检查什么 |
